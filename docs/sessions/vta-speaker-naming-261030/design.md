# DESIGN-note：两人访谈的说话人推测命名，以及证据闸门漏洞修复

## 目标

两人访谈或播客里，即使双方从未叫过对方的名字，网页和导出文本也能显示带「推测」标注的真实身份（例如「说话人1｜作者关联推测:John Collison」），不再一律显示「说话人N 待确认」。名字没认出来时，页面如实提示「部分说话人姓名未识别」，不再误报「说话人区分可能不准」。

## 背景与证据

- 触发案例：生产任务 `task_ed7fcd4384494832b2dc749e73a12daf`，推特视频 2115809881399922849。作者是 John Collison，标题为 "OpenAI's @sama joined me at the pub ..."。FunASR 分出 2 个说话人（84 段和 83 段），全文从未出现对方名字。生产 `speaker_mapping.json` 显示：Speaker1 的候选 John Collison 被误标为 title_credit，判 `quote_missing`；Speaker2 的候选 sama 核对通过，但被 `title_credit_without_dialog_support` 拒绝。
- 生产近 30 天共 65 个 schema v2 任务：全部认出 7 个，部分认出 34 个，一个都没认出 24 个。两人任务 15 个，其中 10 个一个都没认出；这 10 个里有 8 个已有通过核对的标题或作者候选，被规则挡掉。
- 外部顾问咨询（fable5、Codex，2026-10-30，原文 `/tmp/consult-fable.md`、`/tmp/consult-codex.md`）的结论一致：现行规则只保证溯源、不保证校准；它是为 11 人 X Space 加参会名单这种高歧义场景设计的，原样套到两人访谈上就误伤了。两位顾问还发现了现有漏洞（见卡 A）。

## 非目标

- 不修 FunASR 声音分组过度拆分（10 到 29 个说话人的问题）。
- 3 人及以上的场景保持现行规则不变。
- 不把总结环节的人名直接当作说话人映射来源。
- 不用问句占比、发言长度等行为统计作为采用判据（可以写进 meta 做诊断，不参与裁决）。
- 不把 key_info 人名列表接入提示词（可以留作后续增量）。
- 不把 `@sama` 之类的账号名扩写成全名。

## 为什么不是分区 / 删除 / 约定

- **分区**：本方案就是按歧义度分区。只在「恰好 2 个主要说话人，且元数据恰好对应 2 个名字」这个低歧义分区里放宽；其余场景（包括原事故的多人加名单场景）保持原闸门。
- **删除**：「元数据名单独生效」不是无条件开放，只在上述分区里、并且 LLM 明确给出 host/guest 角色时才生效；LLM 可以回答 unknown，此时不采用。整体映射正确与否程序无法证明，所以显示名必须自带「推测」标注，不能当作事实呈现。
- **约定**：显示名沿用现有复合名语法（`说话人N｜作者关联推测:X`），mapping 字符串仍是唯一事实源，渲染层不二次加工；不新增前端状态。

## 方案要点与已否决方案

- **要点**：
  - **卡 A（后端，修现有漏洞）**：
    1. 静态行证据（title_credit / author_host / description_roster）补上名字绑定：候选名必须出现在引用里（忽略大小写），否则判 `name_not_in_quote`。
    2. dialog_address 的引用如果只出现在本人发言样本里，必须是自我介绍句式，否则判新原因 `name_not_self_intro`；引用来自出场前他人发言或旁证条目的，照旧采用。
    3. 修提示词：title_credit 只对应标题；author_host 改为「发布账号署名，不等于出镜者或主持人」。
    4. 规则版本号从 4 升到 5，让旧缓存失效。
  - **卡 B（前端渲染）**：拆分横幅。`low_confidence_cluster_dropped` 对应新文案「部分说话人姓名未识别」；两个矛盾扫描 flag 对应原文案「区分可能不准」；`low_average_mapping_confidence` 不再单独触发横幅。flag 名不改（它们属于 API 字段）。
  - **卡 C（后端，依赖卡 A 合并）**：开放两人元数据推测通路。
    - 前提全部由程序核对：恰好 2 个已采样的主要说话人（按段数占比判断，次要小簇保持占位符）；两人通过核对（含名字绑定）的静态候选恰好给出 2 个不同名字，一人一个；LLM 新增 role 字段（host / guest / unknown），恰好一个 host、一个 guest。
    - 显示名使用元数据原文，例如 `说话人1｜作者关联推测:John Collison`、`说话人2｜标题关联推测:sama`；applied=True；meta 增加 `evidence_tier` 和 `role`。
    - 规则版本号再升一级。
- **已否决**：
  - 用问句占比等行为统计做硬门槛：转录标点是模型补的，嘉宾也会反问，会把旧的点名门槛换成新的行为门槛（两位顾问一致反对）。
  - 对任意说话人数一律显示推测名：多人加名单正是原事故场景。
  - 复用总结环节的人名：它只回答「谁在场」，不回答「哪个声音是谁」。
  - 重命名 `low_confidence_cluster_dropped`：它是 API 字段，可能有外部消费者。

## 关键不变式

1. [实测] 静态行候选名必须出现在引用里。代码：`speaker_inferencer.py` 的 `_verify_candidates`；测试：卡 A 在 `tests/unit/test_speaker_evidence_gate.py` 新增的 Invented Person 反例。
2. [实测] 本人发言里的第三人称提及不能作为 dialog_address 采用。代码：同上；测试：卡 A 新增的 "John Collison wrote about this" 反例。
3. [实测] 元数据推测通路只在恰好 2 个主要说话人、2 个不同名字、host/guest 各一时生效；3 人、unknown 角色、两人同一名字时不生效。代码：卡 C 的 `_decide_display_name` 分支；测试：卡 C 在 `test_speaker_evidence_gate.py` 新增的正反例。
4. [实测] 推测名必须带原编号和「推测」字样，网页与导出文本一致。测试：卡 C 新增的渲染与导出断言。
5. [实测] 命名失败不再显示「区分可能不准」。测试：卡 B 的渲染单测与真浏览器断言。

## 待验证前提

1. [推断] 在生产的两人对谈样本上，开放推测通路后误命名（方向反了）的比例可以接受。验证入口：卡 C 合并部署后，对普查列出的 8 个两人样本加 Collison 案例共 9 个任务重新推断，由人工核对。
2. [推断] 卡 A 的自我介绍句式规则不会大幅减少现有 dialog_address 的命中。验证入口：卡 A 合并后，在普查任务上对比 applied 数量的前后变化。

## 验收路径

1. 入口：生产分享页 `https://sum.zlxlabs.com/view/<token>`，以 Collison 任务为准。
2. 步骤：卡 C 部署后对该任务重新推断说话人，然后打开分享页。
3. 预期：两人分别显示为「说话人1｜作者关联推测:John Collison」和「说话人2｜标题关联推测:sama」，不出现「待确认」，也不出现「区分可能不准」横幅。
